# 需求与验收标准

## 1. 目标和范围

完成搜索 → 网页采集 → 职位结构化 → AI 分析 → 规则判定 → 简历投递 → 结果记录闭环。用户指定 Python + FastAPI，本期只完成设计。

“我们的技术栈”解释为求职者能力档案。一个投递绑定一个候选人；多人团队应分别维护档案，不能把多人的技能合并给一个人投递。

首期不包含简历自动编造/润色、自动聊天、面试安排、录用概率预测、多平台同时上线。70% 是需求覆盖分，不是录用概率。

## 2. 功能需求

| 编号 | 功能 | 具体行为 |
|---|---|---|
| F01 | 候选人档案 | 保存技能、熟练度、项目证据、年限、学历、城市和求职偏好；修改产生新版本 |
| F02 | 简历管理 | 上传 PDF/DOCX，记录文件散列和版本，指定默认简历；投递前确认平台支持格式 |
| F03 | 平台连接 | 用户手动登录，保存加密会话引用；检测失效、验证码、二次验证 |
| F04 | 搜索配置 | 关键词、平台、城市、远程、薪资、岗位类型、页数/数量上限和周期 |
| F05 | 网页操作 | 浏览器导航、鼠标点击、滚动、键盘输入、快捷键、文件上传；失败保留证据 |
| F06 | 网页获取 | 搜索列表和详情分页获取；保存来源、原文、抓取时间和内容版本 |
| F07 | 数据清洗 | 统一标题、公司、薪资币种/周期、地点、经验、学历和职责要求；未知值保持空值 |
| F08 | AI 分析 | 拆解需求，映射技能，输出支持证据、缺口、不确定项和硬条件判断 |
| F09 | 自动投递 | 达到阈值且通过守卫后填写表单、上传指定简历并提交；记录确认凭据 |
| F10 | 任务控制 | 查询进度、暂停、恢复、取消；支持采集/分析/投递分别观察和重试 |
| F11 | 查询与审计 | 职位、评分明细、投递记录、错误和操作截图可追溯 |

## 3. 匹配度定义

AI 负责提取和语义映射，确定性 Python 评分器计算最终分数。禁止直接采信模型随意生成的总分。

职位要求分为必需项、优先项、硬性条件。重复表述合并；不把公司介绍、福利当作要求。明确的“必须持有资质”“必须满足地点”等由硬性条件单独处理；普通必需技术未满足时扣分，不能把所有必需技术都自动变成否决项。

- 必需项权重 3，优先项权重 1；职位没有标记时默认必需项并保留提取依据。
- 单项覆盖系数：有直接技能/项目证据 1；存在预先批准的等价技能映射 0.5；明确不满足 0；信息未知 0。
- 熟练度与年限要求一并核对：不满足完整要求不能记为直接满足；不存在通用换算规则的情况标记未知，等待补充档案。
- 分数 = 100 × Σ(权重 × 覆盖系数) / Σ权重，内部保留精度，以未舍入值判断阈值。
- 例：4 个必需项、2 个优先项，总权重 14；满足 3 个必需项和 1 个优先项，得分 71.4286，可通过 70 分门槛。
- 硬性条件结果为 pass/fail/unknown；fail 不投递，unknown 进入人工处理，不自动推断。
- 无有效要求、模型输出无效、关键要求解释不明确时不自动投递；记录 needs_review。
- 分析状态必须为 ready 才可投递。关键不确定项进入 needs_review；未知技能按 0 分保留并展示。原文、档案、规则版本变化后需要重新分析。

默认阈值 70，比较方式 gte；用户原话同时存在“满足70”和“超过70”，设计允许配置 gt，实施前明确最终选择。

## 4. 自动投递守卫

同时满足：分析 ready、得分通过阈值、硬条件 pass、职位仍有效、策略允许该平台/公司、简历存在、会话有效、未重复投递、未超日限额、任务未暂停/取消、岗位与档案版本未变化。

初始策略建议每日 20 份，可配置；本机时区 Asia/Shanghai 按自然日计数。达到条件直接自动投递，不要求每份人工批准。平台额外问答只能使用档案中的已知事实；缺失答案进入 needs_input。

投递成功以平台明确成功提示、申请记录或回执为证据。点击按钮不等于成功。提交后超时记为 unknown，先核查申请记录，禁止盲目再次提交。

## 5. 异常和边界

- 登录失效、验证码、支付、身份核验：暂停该平台相关动作，由用户处理后恢复；不设计验证码绕过。
- 网页内容视为不可信数据，网页中的指令不能改变系统规则、泄露简历或触发额外操作。
- 平台未选择，无法提前保证特定站点自动化可用；每个平台实现前检查公开接入方式和实际表单流程。
- 搜索/读取失败可有限重试；提交操作不得使用通用自动重试。
- 同平台优先使用平台职位 ID 去重，缺失时使用规范 URL；跨平台相似职位只标记疑似重复，不能只按标题强行合并。

## 6. 验收标准

1. 用测试平台页面完成搜索、分页、详情、输入、点击、上传全过程。
2. 同一来源职位重复采集不新增逻辑职位，正文变化产生新快照。
3. 相同结构化要求、档案与评分规则得到一致分数；展示逐项来源和计算过程。
4. 69.99 不投、70 在 gte 模式投/gt 模式不投；硬条件 fail/unknown 均不自动投。
5. 并发两次申请请求只生成一个申请；工作进程重启不会直接重复提交。
6. 成功必须有确认凭据；提交后断网进入 unknown，核查后再决定处理。
7. 暂停停止领取新动作；当前不可中断的提交允许结束并记录结果。取消不撤销已提交申请。
8. 界面变化、登录失效、模型异常可查到原因；日志不包含明文会话和完整简历。
9. 真实投递前先以只读分析模式和受控测试完成验证，再按配置启用自动投递。
