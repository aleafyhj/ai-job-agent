# 后续实施顺序

第一步工程骨架与第二步数据库层已完成。后续阶段仍逐步等待用户指示，不提前连接招聘账户或执行投递。

| 阶段 | 交付 | 完成标准 |
|---|---|---|
| 1 | 工程骨架、配置、FastAPI、日志 | 本地健康检查、配置加载；依赖锁定 |
| 2 | PostgreSQL 模型与迁移 | 版本、唯一约束、任务租约、申请事务验证 |
| 3 | 档案、简历、策略 API | 支持真实技能证据与不可变版本 |
| 4 | 浏览器执行器与第一个平台适配器 | 手动登录后完成只读搜索/详情采集和分页 |
| 5 | AI 结构化与评分器 | 用标注样本验证需求提取，边界分数和硬条件测试通过 |
| 6 | 持久队列、任务控制与调度 | 重启恢复、暂停/恢复/取消与额度一致性 |
| 7 | 简历表单与自动投递 | 测试页面验证幂等、确认、超时核查；接入真实平台流程 |
| 8 | 管理页与运行交付 | 可查看岗位/评分/申请、处理登录及缺失答案，备份可恢复 |

第一步验证记录（2026-10-29）：Python 3.12.14；6 项 pytest 测试通过，覆盖配置优先级、非法配置拒绝、健康检查、请求追踪、日志隐私和错误响应；Ruff 静态检查与格式检查通过。临时启动本地服务并通过真实 HTTP 验证健康接口、请求 ID 和 OpenAPI 后已停止服务。数据库、worker 与招聘平台仍未接入。

测试重点放在评分依据、重复任务、提交前后崩溃、会话过期、平台表单变化、额度竞争。AI 模型输出不保证每次相同；保存提取结果后，评分计算必须可重复。建立少量人工标注职位样本，评估提取遗漏、误匹配和自动投递误判，达标后再开启策略 auto_apply。

第二步验证记录（2026-10-29）：独立临时 PostgreSQL 18 实例完成 22 张表的迁移往返、Alembic 模型一致性检查及离线 SQL 生成；19 项测试通过（含第一步 6 项及新增配置凭据保护测试）。并发申请只入队一次，跨账户日额度竞争与事务回滚通过，过期任务无法续租。临时实例测试结束后停止，真实应用数据库需按 README 配置。

## 在对应阶段确认的输入

1. 第一个招聘平台已确定为 **BOSS直聘**。搜索入口、实际页面流程、是否支持官方接入、上传简历与确认申请需要实际验证。
2. 候选人真实技术栈、熟练度、项目证据、年限、学历、城市、薪资和远程要求；Python + FastAPI 是本系统开发栈，不能据此推断完整求职能力。
3. 简历文件及允许自动填写的个人信息。
4. 70 分使用 ≥ 还是 >；当前设计默认 ≥。
5. 模型服务商、预算、是否要求本地推理；不预设必须使用某家服务商。
6. 每日上限、搜索周期、允许自动投递的平台与排除公司；初始建议 20 份/日、Asia/Shanghai。
7. 本机是否有可保持登录的 Windows 交互桌面；系统原生键鼠是否为强制要求。Playwright 已覆盖网页鼠标和键盘，原生桌面适配器按实际需要启用。

本机开发数据库连接记录（2026-10-29）：已在现有 PostgreSQL 服务 `127.0.0.1:5432` 内创建独立的 ai_job_agent 数据库和同名非管理员账号；迁移到 0001，22 张业务表验证通过，API 就绪检查返回 200，Alembic 模型一致性检查通过。应用不再使用默认 postgres 管理库；真实凭据只存本地 .env。

这些输入不阻碍当前架构设计；BOSS直聘可行性、AI 提取准确率和性能需要实现阶段验证，目前尚未进行招聘平台的运行测试。
